# 토양 분석 주소 처리 시나리오

주소 제공자와 토양검정 API의 행정구역 명칭·법정동 코드 갱신 시점이 다를 수 있으므로 다음 기준으로 처리한다.

| 시나리오 | 처리 기준 | 기대 결과 |
| --- | --- | --- |
| 일반 지번 또는 도로명 주소 | 카카오 주소 결과의 법정동 코드를 사용한다. | 해당 법정동의 토양검정 결과를 조회한다. |
| 도로명 주소로 변환된 경우 | 입력창에는 사용자의 원문을 유지하고, 백엔드 요청에는 검색된 표준 주소를 사용한다. | 사용자는 주소를 다시 입력하지 않고 상세주소를 선택한다. |
| 시·도 명칭이 변경된 경우 | `ADDRESS_ALIASES`로 현재 주소 제공자가 인식하는 명칭으로 검색한다. | 전북·강원·제주의 이전 명칭도 검색할 수 있다. |
| 주소 API 코드가 토양 API보다 먼저 변경된 경우 | `SOIL_STDG_CODE_ALIASES`에서 토양 API가 보유한 이전 코드로 변환한다. | 용전동의 신규 코드 `1230013600`은 기존 코드 `2917013600`으로 조회한다. |
| 같은 상세주소에 검사 결과가 여러 개인 경우 | 검사일이 최신인 결과 하나만 남긴다. 같은 검사일이면 시료번호가 큰 결과를 사용한다. | 상세주소 선택 목록에 주소당 한 항목만 표시한다. |
| 서로 다른 상세주소인 경우 | 각각의 최신 결과를 유지한다. | 사용자가 필지별 결과를 선택할 수 있다. |
| 토양검정 데이터가 없는 경우 | 임의 데이터를 만들지 않고 조회 실패를 안내한다. | 다른 예시 주소를 시도할 수 있다. |

## 코드 매핑 관리

행정구역 개편으로 새 코드가 추가되면 주소 API의 `b_code`와 토양검정 V2의 실제 조회 결과를 함께 확인한 후 `SOIL_STDG_CODE_ALIASES`에 명시적으로 추가한다. 추측한 접두사 변환은 다른 지역의 정상 코드를 훼손할 수 있으므로 사용하지 않는다.
